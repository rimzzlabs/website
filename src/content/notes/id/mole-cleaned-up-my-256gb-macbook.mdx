MacBook saya M1 Air dengan penyimpanan 256GB. Setahun terakhir, notifikasi "Your disk is almost full" praktis tidak pernah hilang dari hidup saya.

Tiap beberapa minggu ritualnya sama. Kosongkan _trash_, hapus rekaman layar, buang aplikasi yang jarang dibuka. Dapat tiga empat gigabyte, seminggu kemudian habis lagi.

Biang keroknya ada di pengaturan Storage: bagian **System Data**. Puluhan gigabyte, tanpa rincian, tanpa tombol apa pun. macOS tahu persis isinya, tapi tidak mau kasih tahu.

Sampai saya ketemu [Mole](https://github.com/tw93/Mole). Satu malam, dan disk saya lega 12.69 GB. Catatan ini soal apa itu Mole, cara kerjanya, dan kenapa dia tidak akan saya hapus.

## Pendahuluan

Mole adalah _tool_ terminal _open source_ buatan [Tw93](https://github.com/tw93). Bersih-bersih, _uninstall_ aplikasi, analisis disk, optimasi, sampai _monitoring_, semuanya dalam satu _binary_ Go. Perintahnya cuma satu: `mo`.

Pasang lewat Homebrew:

```sh
brew install mole
```

Atau lewat skrip instalasi kalau kamu tidak pakai Homebrew:

```sh
curl -fsSL https://raw.githubusercontent.com/tw93/mole/main/install.sh | bash
```

Selesai. Tidak perlu kasih Full Disk Access ke aplikasi antah-berantah, tidak perlu beli "Mac cleaner" berlangganan dari App Store.

## Satu Perintah untuk Semuanya

Jalankan `mo` tanpa argumen, langsung muncul menu interaktif di terminal. Bisa pakai tombol panah, bisa juga `h`/`j`/`k`/`l` ala Vim. Dari situ saja sudah kelihatan _tool_ ini dibuat oleh orang yang betah di terminal.

Tiap entri menu juga punya _subcommand_-nya sendiri, jadi begitu kamu tahu mau apa, menunya bisa dilewati:

```sh
mo clean      # pembersihan menyeluruh untuk cache dan file sisa
mo uninstall  # hapus aplikasi beserta semua miliknya
mo analyze    # penjelajah isi disk secara visual
mo purge      # bersihkan artefak build dari proyek
mo status     # dasbor kesehatan sistem secara live
```

## Ke Mana Perginya Gigabyte Saya

`mo clean` adalah mode bersih-bersih menyeluruhnya, sekaligus jawaban dari misteri System Data.

Dia menyisir _cache_ aplikasi, _cache_ browser (Chrome, Safari, Firefox), _cache_ perkakas developer seperti Xcode, Node.js, dan npm, log sistem, file sementara, sampai isi _trash_. Semua tempat yang diam-diam diisi macOS tanpa pernah ditunjukkan ke kamu.

Buat mesin developer, _cache_ perkakas developer itu harta karunnya. Xcode paling parah: _derived data_ dan _runtime_ simulator lama numpuk seperti gudang yang tidak pernah dibongkar. _Cache_ npm saya masih menyimpan paket dari proyek yang proyeknya sendiri sudah lama saya hapus.

Sebelum menghapus apa pun, Mole menampilkan tiap kategori lengkap dengan ukurannya, dan kamu yang pilih mana yang dibuang. Ini rincian yang tidak pernah dikasih pengaturan Storage, plus tombol hapusnya sekalian. Begini hasil scan pertama saya:

## Hapus Aplikasi Sampai ke Akarnya

`mo uninstall` menjawab masalah klasik macOS: menyeret aplikasi ke _trash_ tidak benar-benar menghapusnya.

Tiap aplikasi yang kamu hapus dengan cara itu meninggalkan sisa: _preferences_ di `~/Library/Preferences`, _cache_, log, _launch agent_, file pendukung. Satu-satu memang kecil. Tapi setelah bertahun-tahun coba-coba aplikasi, totalnya lumayan untuk disk 256GB.

Mole mencari file bawaan aplikasi di semua lokasi itu dan menghapusnya sekalian. Sisa dari aplikasi yang terlanjur kamu hapus dengan cara lama pun ikut dibersihkan, dan dari situlah sebagian ruang saya balik.

## Kuburan node_modules

`mo purge` dibuat untuk orang seperti saya: folder `~/projects` berisi puluhan eksperimen, dan semuanya masih punya `node_modules` lengkap.

Dia memindai folder proyek kamu, mencari artefak _build_ (`node_modules`, `dist`, `build`, `target` punya Rust, `venv` punya Python), lalu membersihkannya. Kode sumber tidak disentuh sama sekali. Kalau suatu hari kamu balik ke proyek sampingan yang setengah jadi itu, tinggal `npm install` dan semuanya kembali.

Lewat `--paths` kamu bisa menentukan sendiri folder mana saja yang dipindai.

Perintah ini saja sudah cukup jadi alasan pasang Mole. Saya tahu proyek-proyek lama itu ada. Saya cuma tidak pernah sanggup memburu `node_modules`-nya satu per satu.

## Cek Dulu Sebelum Dihapus

_Tool_ bersih-bersih yang jalan dengan `sudo` harus bisa dipercaya dulu, dan di bagian ini Mole kelihatan digarap serius.

Semua perintah yang menghapus sesuatu menerima `--dry-run`: kamu bisa lihat persis apa saja yang akan dibuang tanpa ada satu byte pun yang disentuh.

```sh
mo clean --dry-run
```

Selain itu ada validasi _path_, aturan bawaan untuk folder yang dilindungi, _whitelist_ yang bisa kamu atur untuk hal-hal yang tidak boleh disentuh, dan konfirmasi eksplisit untuk aksi yang berisiko. Semua operasinya tercatat di `~/Library/Logs/mole/operations.log`, dan `mo history` menampilkan catatan itu langsung dari _tool_-nya.

Bawaannya memang sengaja konservatif. Selama saya pakai, dia tidak pernah menyentuh dokumen, foto, atau apa pun yang layak disebut data. Hanya _cache_ dan artefak, hal-hal yang bisa dibuat ulang oleh sistem.

## Penutup

MacBook 256GB di tahun 2026 memang harus dirawat aktif, dan macOS hampir tidak kasih alat untuk itu. Mole mengisi celah itu dengan satu _binary_, menu yang bisa dijalankan pakai tombol Vim, dan bawaan yang cukup hati-hati sampai saya berhenti memeriksa ulang setelah pemakaian pertama.

Kalau pengaturan Storage kamu cuma menampilkan System Data raksasa tanpa penjelasan, coba `mo clean --dry-run` dan lihat sendiri isinya. Paling buruk, kamu tutup terminalnya. Paling bagus, MacBook kesayanganmu dapat napas beberapa tahun lagi.
