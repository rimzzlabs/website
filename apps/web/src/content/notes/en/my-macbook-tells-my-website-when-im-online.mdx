There's a small green dot under my name on the home page now. Next to it, one word: **Online**.

I didn't wire it to a login, a chat app, or a calendar. It's wired to my MacBook. I click a circle in the macOS menu bar, and a few seconds later rimzzlabs.com says I'm here. When the laptop goes to sleep, the dot goes grey and the text turns into "Last active 12 minutes ago."

## Introduction

The idea was simple. I wanted a status I can toggle from my MacBook, on and off, without opening anything.

There was one extra rule: search engines had to see it too. This site is static. Astro builds every page ahead of time, so a status that only appears after JavaScript runs would be invisible to a crawler. The prerendered HTML had to carry the latest state.

That rule shaped everything else, so this note follows the status from my menu bar to the HTML a crawler reads.

## A Button in the Menu Bar

I had two menu bar tools installed: Raycast and Vorssaint. Vorssaint bundles a lot of utilities, but they're fixed tools. There's no way to add your own script, so it can't call an API.

Raycast can. A Raycast extension is a small React project, and one kind of command, `menu-bar`, lives permanently in the macOS menu bar. Give it an `interval` and Raycast runs it in the background:

```json
{
	"name": "presence",
	"title": "Online Status",
	"mode": "menu-bar",
	"interval": "2m"
}
```

That gives me two things from one file. The icon and the menu are the toggle. The two-minute run is a heartbeat.

The command itself is short. Every run sends a `ping`, and the menu items send `on` or `off`:

```tsx
import { getPreferenceValues, MenuBarExtra } from "@raycast/api";
import { useCachedPromise } from "@raycast/utils";
import { presenceUpdateSchema } from "@rimzzlabs/presence";

async function send(action: "on" | "off" | "ping") {
	const preferences = getPreferenceValues<Preferences.Presence>();
	const response = await fetch(preferences.endpoint, {
		method: "POST",
		headers: {
			Authorization: `Bearer ${preferences.token.trim()}`,
			"Content-Type": "application/json",
		},
		body: JSON.stringify({ action }),
	});
	if (!response.ok) throw new Error(`Presence API: ${response.status}`);
	return presenceUpdateSchema.parse(await response.json());
}

export default function Command() {
	const presence = useCachedPromise(send, ["ping"]);
	// ...the icon, plus a Go Online or Go Offline item
}
```

The server ignores a `ping` while the status is off. So the same request also works as "tell me the current state", which keeps the extension to a single endpoint.

## Online, Away, Offline

A toggle alone would lie. If I switch it on and close the lid, the site would say "Online" all night.

The ping fixes that. The toggle says whether I *want* to be visible. The last ping says whether the Mac is actually awake. The status comes from both:

```ts
export function toPresence(row: PresenceRow | null, now: number): Presence {
	if (!row?.last_seen_at) return { status: "offline", lastActiveAt: null };

	const lastActiveAt = new Date(row.last_seen_at).toISOString();
	if (!row.enabled) return { status: "offline", lastActiveAt };
	if (now - row.last_seen_at < ONLINE_WINDOW_MS) {
		return { status: "online", lastActiveAt };
	}
	return { status: "away", lastActiveAt };
}
```

`ONLINE_WINDOW_MS` is five minutes. A ping arrives every two, so the Mac can miss one and still count as online. Two misses in a row usually mean sleep, no network, or Raycast quit.

The state lives in Cloudflare D1, in a table with exactly one row: `enabled` and `last_seen_at`. I picked D1 over KV for a boring reason. A ping every two minutes is about 720 writes a day, and the KV free plan allows 1,000. D1 allows far more, and the site already had a D1 database for the guestbook.

## Static HTML, Live Status

This is the part that makes the search engine rule work.

Rebuilding the site on every toggle would take minutes. Instead, the status is written into the HTML at the edge, per request. Cloudflare Pages already runs a middleware in front of every page, and Workers ship with `HTMLRewriter`, a streaming HTML parser that can edit elements as the response passes through.

Astro renders a hidden placeholder with `data-presence`. The middleware reads the row and fills it in:

```ts
const rewritten = new HTMLRewriter()
	.on("[data-presence]", {
		element(element) {
			markup = toMarkup({ presence, element, now });
			if (markup === null) return;
			element.removeAttribute("hidden");
			element.setAttribute("data-status", presence.status);
		},
	})
	.on("[data-presence-text]", {
		element(element) {
			if (markup === null) return;
			element.setInnerContent(markup, { html: true });
		},
	})
	.transform(response);
```

Here's what a crawler gets from `curl https://rimzzlabs.com/`, no JavaScript involved:

```html
<span data-presence-text>
	<time datetime="2026-11-07T09:20:22.284Z" title="Saturday, November 7, 2026 at 4:20:22 PM GMT+7">
		Online
	</time>
</span>
```

A few details made this hold up:

- The row is cached for 30 seconds, so a burst of page views doesn't turn into a burst of database reads.
- The cache stores the **raw row**, not the computed status. "Online" still flips to "away" on time, even when the row comes from the cache.
- The rewritten response drops its `ETag`. The static file's ETag no longer matches the body, and a browser revalidating with it could get a stale status.
- In the browser, a small script polls `/api/presence` every minute while the tab is visible and updates the text.

## Time That Reads Well

I wanted "Last active" to read like a person wrote it. The rules: minutes or hours under a day, days under three months, and after that, the full date.

`Intl.RelativeTimeFormat` and `Intl.DateTimeFormat` cover all of it, in English and Indonesian, with no date library:

```ts
export function formatLastActive(lastActiveAt: string, now: number, locale: Locale) {
	const elapsed = Math.max(0, now - new Date(lastActiveAt).getTime());
	const lang = HTML_LANG[locale];

	if (elapsed >= RELATIVE_LIMIT_MS) {
		return new Intl.DateTimeFormat(lang, {
			dateStyle: "long",
			timeStyle: "short",
			timeZone: SITE_TIME_ZONE,
		}).format(new Date(lastActiveAt));
	}

	const relative = new Intl.RelativeTimeFormat(lang, { numeric: "always" });
	if (elapsed >= DAY_MS) return relative.format(-Math.floor(elapsed / DAY_MS), "day");
	if (elapsed >= HOUR_MS) return relative.format(-Math.floor(elapsed / HOUR_MS), "hour");
	return relative.format(-Math.max(1, Math.floor(elapsed / MINUTE_MS)), "minute");
}
```

Same input, two outputs: "3 hours ago" and "3 jam yang lalu."

Relative text has one catch for SEO. A search engine can keep a snippet for weeks, and "3 hours ago" is wrong the next day. So the exact time also goes into `<time datetime="…">` and the `title` attribute, where machines can read the real value.

## Things That Bit Me

A few small problems showed up between the first deploy and the first green dot.

**Wrangler used the wrong token.** `wrangler pages secret put` failed with `Authentication error [code: 10000]`. Wrangler reads `.env` automatically, and my `.env` has a `CLOUDFLARE_API_TOKEN` that can only read D1. Wrangler preferred it over my OAuth login. Passing `--env-file /dev/null` makes Wrangler skip the file.

**Secrets belong to a deployment.** On Pages, a secret you add or change applies to the *next* deployment. The running one keeps the old value. So after changing the secret, redeploy, or the API keeps answering 401.

**An old error stayed on screen.** After a successful toggle, the menu still showed `Presence API: 401`. The toggle updated the data but never ran a fresh request, so the error from an earlier ping stayed. Now every toggle is followed by a ping, and a success clears it.

**One token, two places.** The token has to match in the Pages settings and in the Raycast preference. A copied command can replace your clipboard, and a pasted token can carry a line break. I ended up generating a fresh token, setting it in the Cloudflare dashboard, and pasting the same value into Raycast. Both sides also `trim()` the token now.

**TypeScript 7 forgot `fetch`.** The editor flagged `Cannot find name 'fetch'` in the extension, while the command line said everything was fine. The editor used TypeScript 7, which no longer loads `@types/*` packages automatically, so `@types/node` (where `fetch` is declared) never loaded. Listing them fixed it:

```json
{
	"compilerOptions": {
		"types": ["node", "react"]
	}
}
```

## The Repo Grew Up a Little

The extension and the site share types: the response schema, the status rules, the time format. The first version of the extension copied them by hand and used npm, unlike the rest of the repo. So the repo became a pnpm workspace along the way. The site moved to `apps/web`, the extension to `apps/presence`, and shared code into small `@rimzzlabs/*` packages.

One surprise came with it. `@raycast/api` pins `react` to an exact version, and pnpm happily gave the site that newer `react` while `react-dom` stayed one patch behind. Astro's build stopped with "Incompatible React versions." Pinning both in the site's `package.json` settled it.

## Closing

Now when the dot is green, I'm at my desk with the lid open. When it's grey, the text tells you how long ago that was, and the page that tells you is still a static file.

If you want to build your own, the whole thing is in the [source code of this site](https://github.com/rimzzlabs/website): the Raycast extension in `apps/presence`, and the API and middleware in `apps/web/functions`.
