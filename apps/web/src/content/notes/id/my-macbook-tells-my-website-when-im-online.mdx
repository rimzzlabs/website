Sekarang ada titik hijau kecil di bawah nama saya di halaman depan. Di sebelahnya cuma satu kata: **Online**.

Titik itu tidak nyambung ke akun login, aplikasi chat, atau kalender. Dia nyambung ke MacBook saya. Klik satu lingkaran di menu bar macOS, beberapa detik kemudian rimzzlabs.com bilang saya ada. Begitu laptop tidur, titiknya jadi abu-abu dan tulisannya berubah jadi "Terakhir aktif 12 menit yang lalu".

## Pendahuluan

Idenya sederhana: status yang bisa saya nyalakan dan matikan dari MacBook, tanpa buka apa-apa.

Tapi ada satu syarat tambahan. Mesin pencari juga harus bisa lihat. Situs ini statis, semua halaman sudah di-_build_ Astro dari awal. Kalau statusnya baru muncul setelah JavaScript jalan, _crawler_ tidak akan pernah lihat. Jadi HTML hasil _prerender_ harus sudah membawa status terbaru.

Syarat inilah yang menentukan semua keputusan lain. Catatan ini mengikuti perjalanan status itu, dari menu bar saya sampai ke HTML yang dibaca _crawler_.

## Tombol di Menu Bar

Pilihannya ternyata cuma satu.

Di Mac saya ada dua _tool_ menu bar: Raycast dan Vorssaint. Vorssaint isinya banyak, tapi semuanya fitur bawaan. Tidak ada cara untuk menambah skrip sendiri, jadi dia tidak bisa memanggil API.

Raycast bisa. Ekstensi Raycast itu proyek React kecil, dan ada satu jenis _command_, `menu-bar`, yang nongkrong terus di menu bar macOS. Kasih `interval`, Raycast akan menjalankannya di _background_:

```json
{
	"name": "presence",
	"title": "Online Status",
	"mode": "menu-bar",
	"interval": "2m"
}
```

Dari satu file saya dapat dua hal sekaligus. Ikon dan menunya jadi tombol _toggle_. Eksekusi tiap dua menit jadi detak jantung.

_Command_-nya pendek. Setiap eksekusi mengirim `ping`, dan item di menu mengirim `on` atau `off`:

```tsx
import { getPreferenceValues, MenuBarExtra } from "@raycast/api";
import { useCachedPromise } from "@raycast/utils";
import { presenceUpdateSchema } from "@rimzzlabs/presence";

async function send(action: "on" | "off" | "ping") {
	const preferences = getPreferenceValues<Preferences.Presence>();
	const response = await fetch(preferences.endpoint, {
		method: "POST",
		headers: {
			Authorization: `Bearer ${preferences.token.trim()}`,
			"Content-Type": "application/json",
		},
		body: JSON.stringify({ action }),
	});
	if (!response.ok) throw new Error(`Presence API: ${response.status}`);
	return presenceUpdateSchema.parse(await response.json());
}

export default function Command() {
	const presence = useCachedPromise(send, ["ping"]);
	// ...ikon, plus item Go Online atau Go Offline
}
```

Server mengabaikan `ping` selama status mati. Jadi request yang sama sekalian bisa dipakai untuk menanyakan status sekarang, dan ekstensinya cukup pakai satu _endpoint_.

## Online, Away, Offline

_Toggle_ saja bisa bohong.

Kalau saya nyalakan lalu tutup laptop, situsnya bakal bilang "Online" semalaman. Di sinilah `ping` berguna. _Toggle_ menunjukkan apakah saya *mau* kelihatan. Ping terakhir menunjukkan apakah Mac-nya benar-benar menyala. Status diambil dari keduanya:

```ts
export function toPresence(row: PresenceRow | null, now: number): Presence {
	if (!row?.last_seen_at) return { status: "offline", lastActiveAt: null };

	const lastActiveAt = new Date(row.last_seen_at).toISOString();
	if (!row.enabled) return { status: "offline", lastActiveAt };
	if (now - row.last_seen_at < ONLINE_WINDOW_MS) {
		return { status: "online", lastActiveAt };
	}
	return { status: "away", lastActiveAt };
}
```

`ONLINE_WINDOW_MS` itu lima menit. Ping datang tiap dua menit, jadi Mac boleh telat satu kali dan masih dihitung online. Kalau dua kali berturut-turut tidak datang, biasanya laptopnya tidur, internetnya putus, atau Raycast ditutup.

Statusnya disimpan di Cloudflare D1, di tabel yang isinya pas satu baris: `enabled` dan `last_seen_at`. Alasan pilih D1 ketimbang KV itu sederhana. Ping tiap dua menit berarti sekitar 720 kali tulis sehari, sementara KV gratisan cuma kasih 1.000. D1 jauh lebih longgar, dan situs ini memang sudah punya database D1 untuk buku tamu.

## HTML Statis, Status Langsung

Bagian ini yang bikin syarat SEO tadi bisa jalan.

_Build_ ulang seluruh situs tiap kali _toggle_ ditekan butuh beberapa menit. Jadi statusnya ditulis ke HTML langsung di _edge_, setiap ada request. Cloudflare Pages sudah menjalankan _middleware_ di depan semua halaman, dan Workers punya `HTMLRewriter`, _parser_ HTML yang bisa mengubah elemen sambil _response_-nya lewat.

Astro me-_render_ _placeholder_ tersembunyi dengan `data-presence`. _Middleware_ membaca baris di D1, lalu mengisinya:

```ts
const rewritten = new HTMLRewriter()
	.on("[data-presence]", {
		element(element) {
			markup = toMarkup({ presence, element, now });
			if (markup === null) return;
			element.removeAttribute("hidden");
			element.setAttribute("data-status", presence.status);
		},
	})
	.on("[data-presence-text]", {
		element(element) {
			if (markup === null) return;
			element.setInnerContent(markup, { html: true });
		},
	})
	.transform(response);
```

Ini yang didapat _crawler_ dari `curl https://rimzzlabs.com/`, tanpa JavaScript sama sekali:

```html
<span data-presence-text>
	<time datetime="2026-11-07T09:20:22.284Z" title="Saturday, November 7, 2026 at 4:20:22 PM GMT+7">
		Online
	</time>
</span>
```

Ada beberapa detail kecil supaya ini tetap benar:

- Baris D1 di-_cache_ 30 detik. Ramai pengunjung tidak berarti ramai baca database.
- Yang di-_cache_ itu **baris mentahnya**, bukan status hasil hitungan. Jadi "Online" tetap berubah jadi "away" tepat waktu, walaupun barisnya dari _cache_.
- _Response_ yang sudah diubah tidak membawa `ETag` lagi. ETag file statis tidak cocok dengan isinya, dan browser yang memakai ETag lama bisa dapat status basi.
- Di browser, ada skrip kecil yang tanya `/api/presence` tiap menit selama tab-nya terbuka, lalu memperbarui tulisannya.

## Waktu yang Enak Dibaca

"Terakhir aktif" harus terdengar seperti ditulis orang, bukan mesin.

Aturannya: di bawah sehari pakai menit atau jam, di bawah tiga bulan pakai hari, lewat dari itu tulis tanggal lengkap. `Intl.RelativeTimeFormat` dan `Intl.DateTimeFormat` sudah cukup untuk semuanya, dalam bahasa Inggris dan Indonesia, tanpa _library_ tanggal:

```ts
export function formatLastActive(lastActiveAt: string, now: number, locale: Locale) {
	const elapsed = Math.max(0, now - new Date(lastActiveAt).getTime());
	const lang = HTML_LANG[locale];

	if (elapsed >= RELATIVE_LIMIT_MS) {
		return new Intl.DateTimeFormat(lang, {
			dateStyle: "long",
			timeStyle: "short",
			timeZone: SITE_TIME_ZONE,
		}).format(new Date(lastActiveAt));
	}

	const relative = new Intl.RelativeTimeFormat(lang, { numeric: "always" });
	if (elapsed >= DAY_MS) return relative.format(-Math.floor(elapsed / DAY_MS), "day");
	if (elapsed >= HOUR_MS) return relative.format(-Math.floor(elapsed / HOUR_MS), "hour");
	return relative.format(-Math.max(1, Math.floor(elapsed / MINUTE_MS)), "minute");
}
```

Satu input, dua hasil: "3 hours ago" dan "3 jam yang lalu".

Teks relatif punya satu masalah untuk SEO. Mesin pencari bisa menyimpan cuplikan halaman berminggu-minggu, dan "3 jam yang lalu" sudah salah besoknya. Makanya waktu persisnya juga ditaruh di `<time datetime="…">` dan atribut `title`, supaya mesin tetap bisa baca nilai yang benar.

## Yang Sempat Bikin Bingung

Antara _deploy_ pertama dan titik hijau pertama, ada beberapa masalah kecil.

**Wrangler pakai token yang salah.** `wrangler pages secret put` gagal dengan `Authentication error [code: 10000]`. Wrangler otomatis membaca `.env`, dan `.env` saya punya `CLOUDFLARE_API_TOKEN` yang cuma boleh baca D1. Wrangler lebih memilih token itu ketimbang login OAuth saya. Tambahkan `--env-file /dev/null` supaya Wrangler melewati file itu.

**_Secret_ itu milik _deployment_.** Di Pages, _secret_ yang baru ditambah atau diubah baru berlaku di _deployment_ berikutnya. _Deployment_ yang sedang jalan tetap pakai nilai lama. Jadi setelah ganti _secret_, _deploy_ ulang, kalau tidak API-nya bakal terus jawab 401.

**Error lama nyangkut di layar.** Setelah _toggle_ berhasil, menunya masih menampilkan `Presence API: 401`. _Toggle_ memperbarui datanya, tapi tidak menjalankan request baru, jadi error dari ping sebelumnya tidak hilang. Sekarang setiap _toggle_ diikuti ping, dan kalau berhasil, errornya bersih.

**Satu token, dua tempat.** Token di pengaturan Pages dan di preferensi Raycast harus sama persis. Menyalin perintah bisa menimpa isi _clipboard_, dan token yang di-_paste_ bisa ikut membawa baris baru. Akhirnya saya bikin token baru, pasang di _dashboard_ Cloudflare, lalu _paste_ nilai yang sama ke Raycast. Sekarang kedua sisi juga melakukan `trim()` pada token.

**TypeScript 7 lupa `fetch`.** Editor menandai `Cannot find name 'fetch'` di ekstensi, padahal di terminal semuanya lolos. Editornya pakai TypeScript 7, yang tidak lagi memuat paket `@types/*` secara otomatis, jadi `@types/node` (tempat `fetch` dideklarasikan) tidak pernah terbaca. Tinggal sebutkan saja:

```json
{
	"compilerOptions": {
		"types": ["node", "react"]
	}
}
```

## Repo Ikut Naik Kelas

Ekstensi dan situsnya berbagi tipe yang sama: skema _response_, aturan status, format waktu.

Versi pertama ekstensinya menyalin semua itu secara manual dan pakai npm, beda sendiri dari repo lainnya. Jadi sekalian saja repo-nya diubah jadi _pnpm workspace_. Situsnya pindah ke `apps/web`, ekstensinya ke `apps/presence`, dan kode yang dipakai bersama masuk ke paket-paket kecil `@rimzzlabs/*`.

Ada satu kejutan. `@raycast/api` mengunci versi `react` secara persis, dan pnpm dengan senang hati kasih versi `react` yang lebih baru itu ke situs, sementara `react-dom` tertinggal satu _patch_. _Build_ Astro langsung berhenti dengan "Incompatible React versions". Kunci keduanya di `package.json` situs, beres.
